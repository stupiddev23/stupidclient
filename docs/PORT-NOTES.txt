

# ---- ClientCommandSource construction

1.21.11 added a third argument to the client command source:

    1.21.5   (ClientPlayNetworkHandler, MinecraftClient)
    1.21.11  (ClientPlayNetworkHandler, MinecraftClient, PermissionPredicate)

The mod builds one in a static initializer, so the missing argument threw
NoSuchMethodError out of <clinit> and the client came up half-initialized;
the screen-init listener then ran against unset state and died with an NPE.

tools/fixccs.py adds a static bridge on the same class that passes
PermissionPredicate.ALL (field_63208) and rewrites the call site in place at
identical length - aconst_null/getstatic/invokestatic plus four nops - so no
branch offset, stack map frame or exception range moves.  The descriptor used
for the match is the 1.21.5 one; nothing else in the jar builds this class.



# ---- @Inject bridges must return void

mixbridge declares each bridge with the descriptor Mixin expects and then
forwards to the untouched 1.21.5 handler.  For a target that grew a
parameter it also gave the bridge the target's return type and ended it with
CallbackInfoReturnable.getReturnValue() -> unbox -> return.

That is only meaningful once the injection point has run.  At @At("HEAD")
the callback still holds nothing, so TextColor.getRgb unboxed null inside the
copied handler the first time the title screen drew text:

    NPE: ... CallbackInfoReturnable.getReturnValue() is null
        at class_5251.handler$beh002$mioclient$m$$b0

Mixin discards whatever a handler returns - the value the target uses only
travels through the callback - so a handler is always void.  tools/fixbridges.py
cuts the dead tail, discards a forwarded non-void result, and rewrites the
bridge descriptor to end in )V.  The `cancellable` element is left exactly as it was.  Flipping it in place
mis-landed by one byte and produced 17 annotation attributes that ASM rejected
at mixin prepare time ("Index 283 out of bounds for length 206"), aborting the
launch before any class was transformed.  Whether it should be true is still
open; it can only be changed by rebuilding the annotation, never by poking a
byte inside it.  tools/harness/AnnCheck.java parses every class through
ClassNode, the reader Mixin uses, so that damage fails here instead.



# ---- methods that lost their return type

DrawContext.drawTextWithShadow kept its id and its parameters but stopped
returning the width it drew:

    1.21.5   (TextRenderer, String, int, int, int) int
    1.21.11  (TextRenderer, String, int, int, int) void

The title screen handler called it with the old descriptor and threw
NoSuchMethodError the moment the splash overlay drew text:

    NoSuchMethodError: 'int net.minecraft.class_332.method_25303(...)'
        at class_442.handler$bfb000$mioclient$m$$OEp0YT29...

Both call sites throw the result away (`invokevirtual ...; pop`), so
tools/fixvoidcalls.py repoints the constant pool entry at the void
descriptor and turns that pop into a nop.  Same instruction widths, so no
offset, frame or exception range moves.  A call site that used the value
would be reported instead of guessed at.
